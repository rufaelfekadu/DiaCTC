Lexicon-guided decoding

DiaCTC restores Arabic diacritics by choosing a mark for each letter from the audio. A pronunciation lexicon can guide that choice: readings the lexicon lists are free, and anything else costs a penalty.

This page explains the mechanism, walks through one word it fixed and one it broke, and reports the results on CLArTTS and ArVoice.

How it works

The idea

Arabic is normally written without its short vowels, so the letters k-t-b can be read kataba ("he wrote"), kutiba ("it was written") or kutub ("books"). The decoder already knows the letters. Its job is to pick the mark that follows each one.

Without a lexicon, each word is one chain of letters, and after every letter the decoder may take any mark. The audio alone decides, so it can produce a combination that is not a word.

With a lexicon, each known word gets a second set of paths that spell only the readings the lexicon lists. Those paths are free. The original chain stays, but using it costs the lexicon weight.

The steps

  1. Look the word up. The lexicon gives phoneme sequences for an undiacritized word. Each sequence is aligned to the word's letters, which yields one vowel per letter: none, a, i, u, or one of the word-final "-n" endings (an, in, un).
  2. Build the lexicon paths. One path per listed reading, sharing their common beginnings. After each letter the path offers only that reading's vowel.
  3. Charge the free path. The first step of the original chain for that word carries the weight, so it is paid once per word however many letters differ.
  4. Decode. The path with the highest total over the whole sentence wins.

What the weight means

Scores are natural-log probabilities, so a weight of w means an unlisted reading wins only if the audio makes it ew times more likely than the best listed one.

A weight of 0 builds no lexicon paths, so decoding is identical to running without the lexicon.

What is never restricted

  • The last letter of a word. It carries the case ending, and the lexicon is missing many of those.
  • Shadda. The lexicon does not mark doubled consonants, so shadda is always optional.
  • "No mark". Leaving a letter without a diacritic is always allowed.
  • Words the lexicon does not know, and one-letter words. They get no lexicon paths and no penalty.

How a path is scored

The model gives every 20 ms frame of audio a probability for each token: the letters, the marks, and a blank. A path assigns one token to each frame, and its audio score is the sum of the log-probabilities it picks up. Logs of probabilities are negative, so the score closest to zero is best.

The total is the audio score minus any lexicon cost. Scores cover the whole sentence, so only the difference between two readings of a word matters.

Using it

python scripts/inference.py \
    --model_path rufaelfekadu/diactc-combined \
    --manifest_paths <manifest.json> \
    --method wfst \
    --use_blank_token --use_no_diac_token --use_unk_diac_token \
    --lexicon ar-ar_lexicon_2014-03-17.txt --lexicon_weight 2.0

The lexicon is the QCRI ar-ar_lexicon_2014-03-17.txt: 526,119 words in Buckwalter transliteration, each with one or more phoneme sequences. Conversion and alignment are in src/diactc/lexicon.py; the graph is built in build_pattern_fsa in src/diactc/models/base.py.

What to take from it

  • Use a weight around 2 for ArVoice-like text. It lowers DER by about 0.2 points there. Any weight from 0.5 to 4 is at least as good as no lexicon on both sets.
  • Do not use it as a hard constraint. At weight 1000, DER rises from 3.80 to 4.99 on CLArTTS, because correct forms the lexicon lacks are overridden.
  • The ceiling is low. The lexicon cannot tell a non-word from a real form it is missing, and it leaves case endings alone, which is where many of the remaining errors are.
  • The weight was tuned on the test sets, since neither dataset has a dev split, so the gain is an optimistic estimate.
